<section class="sb-proof not-content" aria-label="Why it fits in">
  <div>
    <h2>Your own Claude Code</h2>
    <p>It runs the <code>claude</code> you already use, with your login, settings, commands and skills. Nothing new to sign in to.</p>
  </div>
  <div>
    <h2>Stays on your computer</h2>
    <p>Your prompts and sessions only go where Claude Code sends them. Remote runs only when you turn it on, encrypted from your phone to your computer.</p>
  </div>
  <div>
    <h2>Free and open source</h2>
    <p>MIT licensed and built in the open on GitHub. Signed builds for Mac and Windows, and packages for Linux, that update themselves.</p>
  </div>
</section>

<Feature eyebrow="Stay on top" title="See which session needs you" shot="home" focus="62% 45%" alt="Home: a session that needs you, one that is working, the queue, project tiles to start in, and the usage of two Claude profiles" href="/sessions/sidebar/" linkText="How the sidebar works">
  <p>Every session sits in one list, across every project and every Claude account: the ones you start here and the ones in your terminal. Sessions that <Pill tone="needs-you">Needs you</Pill> go to the top, then the ones that are <Pill tone="working">Working</Pill>, then the rest by day.</p>
  <p>A notification tells you when Claude asks or finishes, so you can look away. <Kbd shortcut="session.next-needs-you" /> jumps to the next session that needs you, from anywhere.</p>

  - [Session states](/sessions/states/)
  - [Home](/sessions/home/)

</Feature>

<Feature eyebrow="Review" title="Catch up in seconds" shot="catch-up-banner" focus="78% 0%" alt="A finished session with its catch-up over the conversation: what Claude did, Commit the changes, 14 tests passed and Followed the plan" href="/sessions/catch-up/" linkText="How catch-up works" flip>
  <p>When a session finishes, a short briefing says what Claude did, what it skipped, and the one thing it needs from you. It shows whether the tests passed, how much changed, and whether Claude stayed inside what you asked for.</p>
  <p>Want to know more? **Ask about this session** in a panel next to it, while it keeps working. Nothing is added to the conversation.</p>

<Feature eyebrow="In parallel" title="Many tasks at once, without the mess" shot="split" focus="20% 30%" alt="Two sessions side by side in split view, each with its own conversation" href="/guides/parallel-sessions/" linkText="Run sessions in parallel">
  <p>Start each task in its own worktree, on its own branch, so sessions never step on each other. Queue the prompts that have to wait, and start them with one click when their project is free.</p>
  <p>Watch two sessions side by side, or give one its own window on another screen. Set a focus limit, and Seshboard asks before you start one more.</p>

<Feature eyebrow="Pipelines" title="Plan, build, check and push in one run" shot="pipeline-parent" focus="62% 20%" alt="A pipeline run under its session: Plan approved on Opus, Execute on Sonnet, Validate checking a second round, and Push waiting for you, each step a sub-session in the sidebar" href="/sessions/pipelines/" linkText="How pipelines work" flip>
  <p>Give one task to a pipeline and each step runs in its own sub-session under it: plan with one model, build with another, have a fresh session check the work, then push. Each step gets what the one before it did.</p>
  <p>When the check still asks for changes, **Another round** sends them back to the build step. Start a run from New session's **Run as**, from a session's menu, or from your phone.</p>

  - [Set up a pipeline](/sessions/pipelines/)
  - [New session](/new-session/form/)
  - [Remote access](/remote-access/)
</Feature>

<Feature eyebrow="On its own" title="Work that starts by itself" shot="upcoming" focus="45% 30%" alt="Upcoming: the queue with one prompt ready to start, the scheduled runs of the next 7 days, the schedules with their switches, and the history of the last runs" href="/sessions/upcoming/" linkText="See Upcoming">
  <p>Schedule a prompt for once, every weekday or every month. Let a trigger start a session, or a whole pipeline, when CI fails on a branch or an issue is assigned to you. A queued prompt starts by itself when the session it waits for is done.</p>
  <p>**Upcoming** shows all of it in one place, across your projects: what is queued, the runs of the next 7 days, and how the last ones went.</p>

  - [Schedules](/new-session/schedules/)
  - [Triggers](/projects/triggers/)
  - [Queue](/new-session/queue/)
  - [Start from a GitHub issue](/sessions/github-issues/)
</Feature>

<Feature eyebrow="Ship" title="From changed files to a pull request" shot="git-checks" focus="100% 0%" alt="A session with the git button showing the pull request's checks, one failing, and Fix failing checks with Claude" href="/terminal-changes-git/git/" linkText="Git in Seshboard" flip>
  <p>See what Claude changed in the **Changes** panel (<Kbd shortcut="changes.toggle" />): stage, unstage or revert files, and open any diff inline. The git button offers the next step: commit, push or create a pull request.</p>
  <p>Once the pull request is open, its checks show on the same button. When one fails, let Claude fix it. A terminal per session is one key away (<Kbd shortcut="terminal.toggle" first />).</p>

  - [Changes](/terminal-changes-git/changes/)

<Feature eyebrow="Anywhere" title="Answer Claude from your phone" shots={[{ name: 'remote-phone-first-screen', alt: 'The remote app on a phone: what needs you, what is working, and the usage of every profile' }, { name: 'remote-phone-drawer', alt: 'The remote app on a phone with the sessions drawer open' }]} shotWidth={300} href="/remote-access/" linkText="Set up Remote">
  <p>Turn on **Remote** and pair your phone. Follow your sessions, allow what Claude asks, send the next prompt or start a new session, wherever you are. Your phone gets a notification when a session needs you.</p>
