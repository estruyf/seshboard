New session is where every Claude Code session starts. You pick a project, choose whether Claude works on your checkout or in a new worktree, write the first prompt and press **Start**.

<Screenshot name="new-session" alt="The New session view: the heading Where do we start?, four project tiles with one picked, and the message box below with a typed prompt, the route strip above it and the profile, model, effort and mode chips under it" eager />

## Open it

- Press <Kbd shortcut="session.new" />.
- Click the yellow **+** button at the top of the sidebar.
- In the command palette, run *New session…* to do it all from the keyboard (see [Start from the palette](#start-from-the-palette)), or *New session in &lt;project&gt;* for the project you have open.
- On a project's page, <Kbd shortcut="session.new" /> and its **New session** button start in that project.

When you left a prompt unsent in New session, the **+** button carries a small pen and opens New session on that prompt's project. See [Unsent messages](/sessions/unsent-drafts/).

## Pick a project

The view opens with the heading *Where do we start?* and your first four projects as tiles. Each tile shows the project's icon, its name and what is going on there: <Pill tone="needs-you">1 needs you</Pill>, <Pill tone="working">2 working</Pill>, or how long it has been idle.

- Press <Kbd shortcut="new-session.pick" /> to pick a tile by its number. This works wherever focus is, also while you type the prompt.
- **Filter**, at the right of the *Project* heading, opens all projects with a filter field. With more than four projects, the fifth tile, **+N more**, does the same. Type a few letters of a name; the field shows how many match, such as "2 of 9". Typing a letter while a tile has focus opens the list filtered by it. <Kbd keys="enter" /> picks the highlighted project, the arrow keys move.
- **Quick question**, under the tiles, starts without a project. See [Quick questions](/new-session/quick-questions/).

The order of the tiles follows *Project order* in [Settings → Projects](/settings/#projects): *Recent* (the ones you used last first) or *Your order*. New session remembers the last project you picked and opens on it next time. A project you filtered the sidebar to is picked first.

### Add a folder

Adding a folder takes one step. The folder becomes a project and is picked right away. A folder that already is a project is only picked.

- **Add project…**, at the right of the *Project* heading, opens the same **Add project** dialog as [Projects](/projects/projects-view/#add-a-project): the folders you have used Claude Code in, and **Choose folder…** for any other. The project you add is picked here, and you stay in New session. With the list open, the button sits next to the filter field. In the command palette, *Add project…* does the same while New session is open.
- Type a path in the filter field: one that starts with <Os mac="~/ or /" windows="~\ or a drive, such as C:\" />. The field turns into a path field and lists the folders in it, with the branch of the ones that are git repositories. The rest of the first folder shows faintly after what you typed: <Kbd keys="tab" /> takes it, and <Kbd keys="tab" /> on a whole folder name goes into it. <Kbd keys="enter" /> on a folder (its row says **Add and start here**) adds it and picks it. Hidden folders show when you type a dot.
- When a name matches none of your projects, the list shows the folders Claude Code already has sessions for that aren't projects yet. <Kbd keys="enter" /> adds the highlighted one. The last row, **Choose a folder…**, opens the folder dialog.
- Drag a folder from <Os mac="Finder" windows="File Explorer" /> onto the projects and drop it. Files, or several items at once, are not added.

Without any projects yet, one wide tile, **Add project…**, opens the same dialog. You can also start typing a path there.

### Clone from GitHub

With [Clone from GitHub](/projects/clone-from-github/) on in Settings › Projects, **Clone from GitHub…** sits next to **Add project…**. It replaces the tiles with a form: paste a repository's URL, check the folder it goes in, and press <Kbd keys="enter" /> to clone. A GitHub URL pasted in the filter field offers **Clone owner/name** too. Type the prompt while it clones: Start waits for the clone, then starts the session in it. **Pick a project instead** goes back to the tiles.

When you pick a folder that isn't one of your projects yet, a checkbox under the message box, **Add &lt;folder&gt; to your projects**, adds it when the session starts. Leave it ticked to find the folder in New session next time.

Under the message box, **Pick up in &lt;project&gt;** lists the project's recent sessions with their state, so you can continue one instead of starting another. **Queued in &lt;project&gt;** lists the prompts you queued there.

## Choose where Claude works

The strip on top of the message box says where the session runs. It shows the project, then where the edits land, then the branch. Hover it for a plain sentence, such as "Edits land directly in your working copy on main".

- **Current checkout** (the default): Claude edits your working copy.
- **New worktree**: Claude gets an isolated copy of the repository on a branch of its own. Flip the **Worktree** switch at the right of the strip, or pick it in the menu. See [Worktrees](/new-session/worktrees/).

### Work on another branch

On the current checkout, the branch button lists your local branches, with a search field. Pick one to check it out before the session starts. The current branch is marked `current`, with `↓3` when its upstream has commits you don't have.

Switching uses git's own checkout: uncommitted changes that don't conflict come along, and git refuses when they would be overwritten. Nothing is stashed or thrown away.

A branch that is checked out in another worktree (such as one Claude Code made in `.claude/worktrees`) is listed but can't be picked: git won't check out a branch twice. It says *Checked out in another worktree*. When a branch kept from before is one of them, **Start** says so; **Start in a new worktree** and **Add to queue** still work.

A folder that isn't a git repository shows `no git`, and Claude edits the folder directly.

### Update from remote

Your copy may be behind the remote. The button at the top right of New session offers the next step: **Fetch** to see whether the upstream moved on, or **Pull ↓2** when it did. Its ▾ menu has both. After a pull it says "Pulled 2 commits", after a fetch with nothing new "Up to date". In the command palette, *Update from remote* runs the same step.

Next to it, the **Open in** button opens the project in your editor, terminal or <Os mac="Finder" windows="File Explorer" />.

## Write the prompt

The message box works the same as in a session, except that <Kbd keys="arrowup" /> brings back no earlier messages here:

- <Kbd shortcut="composer.send" /> starts, <Kbd shortcut="composer.newline" /> adds a new line.
- Type <Kbd shortcut="composer.commands" /> for commands and skills, <Kbd shortcut="composer.mention" /> to mention a file.
- Paste, drop or attach images, and add files as context with <Kbd shortcut="composer.add-context" />, from the project or from anywhere on your computer with **Choose in <Os mac="Finder" windows="File Explorer" />…**. A long paste goes in a [Pasted card](/sessions/conversation/#pasted-text).

The box takes the colour of the picked project, with a faint ring around it.

Under the message box sit the chips for the Claude profile (with more than one profile), the model, the effort and the permission mode. They show only the value, such as "Opus 4.5", "Medium" or "Auto". See [Model, effort and mode](/new-session/models-and-options/). On the right of that line you see your plan usage for the profile the session uses.

Prompts you write here and don't start are kept per project, also after you quit. Pick the project again and the prompt comes back, with a banner that says so and a **Discard** button.

## Start a session

**Start** is a split button. The main part starts the session (<Kbd shortcut="new-session.start" />). The ▾ next to it holds the other ways to start:

| Choice | Shortcut | What it does |
|---|---|---|
| **Start session** | <Kbd shortcut="new-session.start" /> | Starts the session with the choices on screen. |
| **Add to queue** | <Kbd shortcut="new-session.queue" /> | Keeps the prompt, project and choices in the [queue](/new-session/queue/) to start later. |
| **Schedule…** | | Opens [Schedule a session](/new-session/schedules/) for the prompt. |
| **Start when…** | | Makes a [trigger](/projects/triggers/) that starts the prompt when CI fails or an issue is for you. |
| **Start in a new worktree** | | Starts this one session in a new worktree, leaving the route and the project's default as they are. Shown in a git repository while the route is the current checkout. |

**Run as**, next to Start in a git repository, says **One session**. Pick a [pipeline](/sessions/pipelines/) there, and Start becomes **Run pipeline**: it runs the pipeline with the prompt as its task, and its steps show under the message box. **Start one session** in the ▾ starts a single session instead.

When something stops Start, its tooltip says why: "Type a message first", "Choose a folder first", or the focus limit.

The session opens as soon as it starts. Claude Code was already warmed up in the folder while you typed, so the first reply comes quickly.

## Project defaults

New session starts from the project's defaults: model, effort, permission mode, current checkout or worktree, what a worktree branches from, and a branch. Fields the project leaves unset use the [defaults of the session's Claude profile](/settings/claude-profiles/#defaults-for-new-sessions), then Claude Code's own defaults. The permission mode follows **Permission mode** in [Settings › General](/settings/#new-sessions), which can also remember the last one you picked or always use one.

Change something in New session, and it applies to that prompt only: the next one starts from the project's defaults again (the permission mode too, unless Settings › General says **Remember last**). To keep it, open the **Where** menu (the route button in the strip) and choose **Save as project default**, or run *Save as project default* in the command palette. A line under the message box confirms it ("Saved as acme-store's defaults"). The menu item says **Saved** when the choices on screen already are the defaults.

You can also edit the defaults on the project's [Settings tab](/projects/settings/).

## Pick a profile for one session

With more than one [Claude profile](/settings/claude-profiles/), the first chip under the message box shows the profile the session runs on. It starts on the project's profile, or the default one, marked "(project)" or "(default)" in the menu. Pick another for this session only. The usage on the right follows the profile you pick.

## Run on another computer

<Screenshot name="computers-new-session" alt="New session with Run on set to mystic: three project tiles from mystic with a monitor badge, the strip above the message box with mystic, the project and Current checkout, and Start on mystic, with a line under it that Claude runs on mystic" />

With [another computer paired](/other-computers/), **Run on** sits under the heading: <Os mac="This Mac" windows="This PC" /> and each paired computer, with a green dot when it is connected. Pick a computer and Claude runs there, in its folders and with one of its Claude profiles. You follow the session from here.

- The tiles are that computer's projects, each with a small monitor badge. <Kbd shortcut="new-session.pick" /> still picks one, and **+6 more on mystic** shows the rest. Folders on another computer can't be picked from here, so there is no **Other folder** or **Add project…**.
- The strip above the message box starts with the computer's name, then the project. **Where** (the current checkout or a new worktree) and the chips under the message box show when the other computer's Seshboard offers them. An older version only takes the project and the prompt.
- On the current checkout, the strip ends with the branch checked out on that computer. Click it to pick another local branch, with a search field, as in [Work on another branch](#work-on-another-branch): it is checked out there before the session starts. A branch checked out in another worktree can't be picked. This needs this version of Seshboard on the other computer.
- The chips start from the project's defaults on that computer. With more than one Claude profile there, the first chip is the profile: the project's own, else that computer's default, marked "(project)" or "(default)" in the menu. Pick another for this session only, and the other chips show that profile's defaults where the project sets none. With [Auto model](/new-session/auto-model/) on there, the model list starts with **Auto**. The effort chip only shows for a model that takes an effort.
- **Start on mystic** (<Kbd shortcut="new-session.start" />) starts the session there and opens it here.
- Attach images and files with the paperclip button, or paste or drop them on the message box, as for [a session there](/other-computers/#send-images-and-files). They go to the other computer with the prompt. Your [saved prompts](/sessions/saved-prompts/) for every project work there too: type `/` or click a chip above the message box. Quick question, **Add to queue** and the focus limit are for this computer only.
- With [Clone from GitHub](/projects/clone-from-github/#on-another-computer) on here, **Clone from GitHub…** clones on that computer, into its own **Clone into** folder, and starts the session there.

An offline computer stays in the switch, greyed out, with when it was last seen. The **+** button in the sidebar starts on this computer, unless you typed a prompt for another computer and didn't start it: then it opens there, with your prompt. <Kbd shortcut="session.new" /> always starts on this computer. **New session on mystic…** in the command palette opens New session with that computer picked.

## At the focus limit

With the [focus limit](/focus-limit/) on and reached, a note above the message box lists the sessions that count, each with **Open**, and **Change limit** opens Settings. Its **Add to queue** keeps the idea for later.

- **Nudge**: Start asks first, and the note also has **Start anyway**.
- **Strict**: Start waits until you finish, read or archive a session. **Add to queue** stays in Start's menu.

## Start from the palette

The command palette can start a session without leaving the keyboard.

<Steps>

1. Press <Kbd shortcut="palette.commands" first /> and choose *New session…*, or type `+` in the palette.
2. Pick a project: type a few letters, or press <Kbd shortcut="new-session.pick" />. <Kbd keys="alt+enter" /> picks it in a new worktree, and <Kbd keys="mod+o" /> chooses another folder.
3. Write the prompt in the small New session form. It has the route, the branch and the same chips.
4. Press <Kbd keys="mod+enter" /> to start, or <Kbd keys="mod+shift+enter" /> to add it to the queue.

</Steps>

<Kbd keys="mod+e" /> moves the prompt and choices to the full New session view. <Kbd keys="escape" /> closes the palette and keeps what you typed as the project's unsent prompt. See [Command palette](/command-palette/).

## Start from a link

A `seshboard://new-session` link opens New session with a project and a prompt filled in. You read the prompt and press Start yourself, unless the link says `autostart=1`. A line under the message box says the prompt came from a link, with **Clear**. See [Links](/links/).

## Settings

- [Settings → General](/settings/#general): Seshboard can open on New session.
- [Settings → Projects](/settings/#projects): *Project order* sets how the tiles are ordered, and [Clone from GitHub](/projects/clone-from-github/) turns on cloning a repository from New session.
- [Settings → Claude profiles](/settings/#claude-profiles): the profiles you can pick from.
- [Settings → Focus](/settings/#focus): the focus limit.
- A project's [Settings tab](/projects/settings/): its defaults and profile.
