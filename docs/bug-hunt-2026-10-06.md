### Fixing (five agents in parallel, one per area, no shared files)

**Engine hosts (H1–H7), all fixed.**
- H1: a fork gets its own id up front (`randomUUID()`, new `HostConfig.forkFrom`). The SDK accepts `sessionId` with `resume` + `forkSession: true` (checked in `sdk.d.ts`/`sdk.mjs` 0.3.288). The host is stored, broadcast and fed under the new id from the start. `session.send` still returns `{ sessionId: <fork id> }`, so the UI is unchanged. The re-key on `init` stays as a fallback for older `claude` binaries.
- H2: `ensureHost` keeps a `starting` map; concurrent resumes await the same start (old body is now `startHost`).
- H3: `prewarm` uses a generation counter (bumped by `discardWarm`/`closeAll`) and a `warming` target, so overtaken pre-warms never start a process.
- H4: `UsageMonitor` has a `stopped` flag, retries a miss only once, clears the deadline in `finally`, reports a timeout as a timeout, and takes an optional `timeoutMs` for tests.
- H5: `recentlyClosed` uses the later of the two stop times.
- H6: `SessionHost.release()` ends the input queue and drops the `Query` on close and on natural exit. Closed hosts stay in the map on purpose (the UI shows their Failed state).
- H7: AGENTS.md now names `usageMonitor.ts` as the one documented exception to the `query()` and "no prompt" rules.
- Tests: fork tests updated, plus new tests for forking a running session, concurrent sends, overlapping pre-warms, `closeAll` during pre-warm, usage retry/stop/timeout, stale stop time, input ending. The new H1–H5 tests were run against the old code and fail there.

**Engine core (E1–E14), all fixed.**
- E1: a cache from a newer build (or one that fails to migrate, or is locked) is **never touched**. This run uses a side file `cache.sqlite.v<N>` that persists between launches of that older build. Only SQLite's own corruption codes (SQLITE_CORRUPT, SQLITE_NOTADB) move the file aside, now together with its `-wal`/`-shm` (moved before close, because closing deletes the WAL). Opening a newer schema in place was rejected: v13 renames and drops columns, so older queries could fail or write rows the newer build misreads. New `CacheDatabase.fallback` field, logged by the engine.
- E2: `GIT_LITERAL_PATHSPECS=1` on every `git()` call (all callers checked; none relies on globs).
- E3: revert decides with `cat-file -e HEAD:<path>`; staged deletions are restored; renames restore the old path and unstage/trash the new one (old path found from porcelain, so no protocol change). `fileDiff` handles both.
- E4: `assertCheckoutIdle` before a branch switch in `session.create` (only when the branch changes), before merge, and before worktree removal (new `except` parameter so the finishing session isn't counted).
- E5: the index creates a missing `projects/` folder when the profile folder exists, retries unwatched folders on each refresh, and drops a failed watcher so it is re-added.
- E6: a full scan skips ids that changed or were forgotten while it waited.
- E7: shared `parsePorcelain` checks both status columns for renames/copies.
- E8: unstaging without a HEAD uses `git rm --cached`.
- E9: untracked files are counted in-process (`countNewLines`, same rules as git: binary counts 0, 512 KB+ counts 0, 16 MB read budget).
- E10: file search is async, breadth-first, stops after 1.5 s, and skips Library, Desktop, Documents, Downloads, Pictures, Movies and Music in the home folder.
- E11: one dispose hook per connection for terminal viewers; empty viewer sets are removed.
- E12: project icons must resolve inside the project root (checked before and after following symlinks; `../../media/icon.svg` from a monorepo package still works).
- E13: every parsed `git diff` runs as `git -c diff.suppressBlankEmpty=false diff --no-ext-diff --no-color`.
- E14: `rpc.call` cleans up and rejects with DISCONNECTED when `send` throws.
- Tests: database (newer schema untouched, failed migration kept, WAL moved with a corrupt file, error classification), git (glob names, staged deletion, staged rename, worktree rename, unborn unstage, line counts vs git, hostile diff config), engine (SESSION_BUSY for the three branch paths), sessions (new profile folder, scan race), projects (icon containment), files, rpc.
